    プロダクト要求定義書 (Product Requirements Document)

    プロダクト概要

    名称

    BentoSales - 仕出し弁当業務に特化した軽量販売管理システム

    プロダクトコンセプト

    • 電話注文に最適化された高速入力: 電話を受けながらでも素早く注文を入力できる、画面遷移最小の1画面完結型UI
    • 注文から請求・入金まで一貫管理: 注文入力→製造確認→帳票出力→請求→入金登録のすべてを一つのシステムで完結
    • 顧客ごとの複雑な取引条件に対応: 単価・税区分・支払方法・締め日が顧客ごとに異なる仕出し業態の商慣行に完全対応

    プロダクトビジョン

    仕出し弁当店のオーナーとスタッフが、電話注文受付から請求・入金管理まで、すべての業務をシンプルな一つのWebシステムで完結できる環境を提供する。 紙やExcelへの手作業転記をなくし、注文ミス・集計ミス・請求漏れをゼロに近づける。 電話しながら操作できる直感的なUIで、業務の流れを止めることなく素早く入力・確認できる。 厨房への製造一覧共有から、PDF帳票（請求書・領収書・納品書）の発行まで、仕出し弁当業務に必要な機能を過不足なく提供する。

    目的

    • 電話注文の手書きメモ・後から転記というミスが起きやすい業務フローを廃止する
    • 日々の製造数集計を自動化し、厨房への情報共有をリアルタイムにする
    • 顧客ごとに異なる請求条件（都度/月締め/指定日締め）に対応した請求書を自動生成する
    • 売掛管理（未払い・一部入金・入金済）をシステムで一元管理し、入金確認漏れをなくす
    • 請求書・領収書・納品書・製造一覧をPDFで出力し、帳票管理を効率化する

    ターゲットユーザー

    プライマリーペルソナ: 店舗スタッフ（電話注文受付担当）

    • 仕出し弁当店で電話注文を受け付ける担当者（パート・アルバイト含む）
    • PC操作は一般レベル（複雑なUIは使いこなせない）
    • 電話しながら同時に入力するため、画面から目を離せない場面が多い
    • 課題: 電話中に商品・数量・顧客情報を聞きながら同時入力するため、画面遷移や複雑な操作があると注文を聞き漏らす
    • 期待する解決策: 顧客選択と商品追加が同一画面で完結し、キーボードを主体に高速入力できること
    • 典型的なワークフロー: 電話を受ける → 顧客を選択 → 商品と数量を入力（複数行） → 保存 → 次の電話を待つ

    セカンダリーペルソナ: オーナー

    • 売上管理・請求管理・入金管理を担うオーナーまたは経理担当者
    • PC操作は一般レベル
    • 月次での請求業務と、顧客ごとの売掛状況の確認が主な業務
    • 課題: 顧客ごとに締め日・税区分・支払方法が異なるため、請求書作成に毎月多くの時間がかかる。売掛の未入金確認も手作業で漏れが発生する
    • 期待する解決策: 顧客設定に基づいて請求書が自動生成され、未入金一覧が一目でわかること
    • 典型的なワークフロー: 月末に請求対象を確認 → 請求書PDF発行 → 入金確認後に入金登録 → 領収書PDF発行

    成功指標 (KPI)

    プライマリーKPI

    • 注文入力時間の短縮: 電話注文1件の入力完了時間を1分以内に短縮（導入3ヶ月後）
    • ベースライン計測: 導入前2週間、スタッフが注文1件ごとに所要時間を記録する
    • 注文内容の誤り削減: 注文内容・数量・単価の入力ミスが月5件以下になる（導入3ヶ月後）
    • ベースライン計測: 導入前1ヶ月の誤り件数を手書きログで記録する
    • 請求書作成時間の短縮: 月次請求書作成にかかる時間を30分以内に短縮（導入3ヶ月後）
    • ベースライン計測: 導入前の月次請求書作成にかかる時間をオーナーが記録する

    セカンダリーKPI

    • 売掛未回収件数の削減: 入金確認漏れによる未回収が月0件（導入3ヶ月後）
    • PDF帳票の再発行対応時間: 過去帳票の再発行を30秒以内に完了できる
    • システム稼働率: 99%以上（営業時間内）

    機能要件

    コア機能 (MVP / P0)

    1. 注文入力

    ユーザーストーリー: 店舗スタッフとして、電話注文を受けながらミスなく素早く入力するために、1画面で顧客選択と複数商品の注文入力が完結する機能が欲しい

    受け入れ条件: - [ ] 顧客をプルダウンで選択できる（顧客名で検索絞り込み可能） - [ ] 商品を行ごとにプルダウンで選択し、数量を入力できる（複数行追加可能） - [ ] 顧客設定の単価・税区分に基づいて単価・小計・税額・税込合計が自動計算される - [ ] 注文入力中に商品別集計がリアルタイムで更新される - [ ] 単価を手動で上書き入力できる（入力値が顧客別単価・標準単価より優先） - [ ] 「前回注文コピー」ボタンで同顧客の直近注文内容（商品・数量・単価）をコピーできる - [ ] 保存ボタンで注文を確定できる - [ ] 適用中の単価種別（手動入力/顧客別単価/商品標準単価）がアイコンまたは色で視覚的に区別できる

    画面レイアウト（参考）: 

    顧客: [山田商事 ▼]  配送日: [2026-05-08 ▼]

------------------------------------------------
| 商品 ▼      | 単価  | 数量 | 金額  | 削除 |
------------------------------------------------
| 唐揚げ弁当 ▼ |  800  |  10  |  8,000|  ×  |
| 幕の内弁当 ▼ |  900  |   5  |  4,500|  ×  |
------------------------------------------------
                          [+ 商品追加]

税抜合計:  12,500
消費税  :   1,250
税込合計:  13,750

[前回注文コピー]      [保存]

    優先度: P0（必須）

    2. 注文一覧・編集

    ユーザーストーリー: 店舗スタッフとして、当日の注文状況を素早く確認・修正するために、全注文を一覧で表示しインライン編集できる機能が欲しい

    受け入れ条件: - [ ] 指定した日付の注文一覧をグリッド形式で表示できる（顧客名・商品名・単価・数量・金額） - [ ] グリッド上で数量・単価を直接編集できる - [ ] グリッド上での編集後、グリッド専用の「変更を保存」ボタンを押すことで変更が確定される（セル移動では自動保存しない） - [ ] 注文行を削除できる - [ ] 日付切替で別日の注文一覧に切り替えられる - [ ] 顧客別合計金額が一覧の右下またはサイドパネルに表示される

    優先度: P0（必須）

    3. 商品別集計（製造一覧）

    ユーザーストーリー: 店舗スタッフ・厨房担当者として、当日何をいくつ作るかを確認するために、商品別の合計数が一覧で見られる機能が欲しい

    受け入れ条件: - [ ] 指定日の全注文から商品ごとの合計数量を集計して表示できる - [ ] 注文の追加・変更・削除に連動してリアルタイムに更新される - [ ] PDF（製造一覧）として出力できる

    優先度: P0（必須）

    4. 顧客管理

    ユーザーストーリー: オーナーとして、顧客ごとの取引条件を管理するために、顧客情報と請求設定を登録・編集できる機能が欲しい

    受け入れ条件: - [ ] 顧客の基本情報（顧客名・電話番号・住所・担当者名・備考）を登録・編集できる - [ ] 顧客ごとの税区分（外税・内税）を設定できる - [ ] 顧客ごとの支払方法（現金・振込・引落など）を設定できる - [ ] 顧客ごとの締め種別（都度・月締め・指定日締め）と締め日を設定できる - [ ] 顧客ごとの商品別単価（顧客別単価）を登録できる - [ ] 顧客を有効/無効に切り替えられる（無効顧客は注文入力の選択肢に表示しない）

    優先度: P0（必須）

    5. 商品管理

    ユーザーストーリー: オーナーとして、販売商品を管理するために、商品の基本情報を登録・編集できる機能が欲しい

    受け入れ条件: - [ ] 商品名・標準単価・税率・有効/無効を登録・編集できる - [ ] 無効にした商品は注文入力の選択肢に表示されない - [ ] 商品一覧を表示できる

    優先度: P0（必須）

    6. 請求管理

    ユーザーストーリー: オーナーとして、顧客への請求を正確に行うために、顧客の締め条件に基づいて請求書を生成できる機能が欲しい

    受け入れ条件: - [ ] 顧客の締め種別（都度・月締め・指定日締め）に基づいて請求対象の注文を自動抽出できる - [ ] 請求書を手動で生成できる（対象注文を選択して生成） - [ ] 請求書番号が自動採番される（例: INV-202605-0001） - [ ] 生成した請求書の内容（請求書番号・顧客・対象期間・明細・合計）を確認できる - [ ] 請求書をPDFとして出力できる - [ ] 請求書の状態（未送付・送付済・入金待ち・入金済）を管理できる - [ ] 既に請求書に紐づいた注文は請求書生成時の対象選択に表示されない（未請求の注文のみ選択可能） - [ ] 注文一覧で「請求済み / 未請求」が識別できる（バッジまたは色で区別） - [ ] 請求書は削除不可。キャンセル操作のみ可能で、キャンセル時は対象注文が未請求状態に戻る

    優先度: P0（必須）

    7. 入金管理

    ユーザーストーリー: オーナーとして、売掛の入金状況を把握するために、請求書ごとの入金登録と売掛一覧を管理できる機能が欲しい

    受け入れ条件: - [ ] 請求書に対して入金額・入金日・入金方法を登録できる - [ ] 入金状態（未払い・一部入金・入金済）が自動更新される - [ ] 未払い・一部入金の請求書一覧を表示できる（売掛一覧） - [ ] 入金済み後に領収書をPDFとして発行できる - [ ] 領収書番号が自動採番される（例: REC-202605-0001）

    優先度: P0（必須）

    8. PDF帳票出力

    ユーザーストーリー: オーナー・スタッフとして、顧客への書類を正確かつ迅速に発行するために、各種帳票をPDFで出力できる機能が欲しい

    受け入れ条件: - [ ] 請求書・領収書・納品書・製造一覧の4種類をPDFで出力できる - [ ] 納品書番号が自動採番される（例: DEL-202605-0001） - [ ] 過去に発行したPDFを再発行できる - [ ] PDFにはプロダクト名・発行日・顧客情報・明細・合計が含まれる

    優先度: P0（必須）

    重要機能 (P1)

    9. ダッシュボード・集計

    ユーザーストーリー: オーナーとして、売上状況を把握するために、期間別・顧客別の売上集計を確認できる機能が欲しい

    受け入れ条件: - [ ] 指定期間の売上合計・顧客別売上を確認できる - [ ] 売掛残高の合計が確認できる

    優先度: P1（重要）

    10. キーボード操作最適化

    ユーザーストーリー: 店舗スタッフとして、電話しながら素早く注文を入力するために、マウスなしでキーボードのみで注文入力が完結できる機能が欲しい

    受け入れ条件: - [ ] 注文入力フォーム内でTabキーにより顧客→商品→数量→単価の順にフォーカスが移動する - [ ] Enterキーで次の入力行に移動できる - [ ] 数量入力後にEnterキーで商品追加行にフォーカスが移る

    優先度: P1（重要）

    11. インボイス対応帳票

    ユーザーストーリー: オーナーとして、適格請求書発行事業者として法的に正しい請求書を発行するために、インボイス制度対応フォーマットの帳票が欲しい

    受け入れ条件: - [ ] 請求書に適格請求書発行事業者登録番号（T+13桁）を印字できる - [ ] 税率ごとの課税金額・消費税額を区分して記載できる - [ ] インボイス制度（適格請求書等保存方式）の記載要件を満たすフォーマットで出力できる

    優先度: P1（重要）

    将来的な機能 (Post-MVP / P2)

    12. 受渡チェック

    • 注文ごとの「渡し済み」チェックを管理する軽量な配達確認機能

    優先度: P2（できれば）

    13. 帳票カスタマイズ

    • 会社ロゴの印字
    • 印影の印字

    優先度: P2（できれば）

    非機能要件

    パフォーマンス

    • 注文保存のレスポンスタイム: 500ms以内
    • 注文一覧表示（当日100件以内）: 1秒以内
    • 商品別集計のリアルタイム更新: 200ms以内
    • PDF生成: 3秒以内

    ユーザビリティ

    • 初めて使うスタッフが10分以内に注文入力の基本操作を習得できる
    • 電話中でも片手・目線を電話側に向けた状態でキーボード入力が完結できる
    • モバイル対応スコープ: 製造一覧表示のみ（読み取り専用）をスマートフォンのブラウザで正常に表示できること。その他の画面はモバイル最適化の対象外

    信頼性

    • 注文データのデータ損失ゼロ（データベースへの即時永続化）
    • 発行済みPDFを再発行できる（帳票履歴の永続保存）
    • 注文時点での単価・税率・税額を固定保存し、後からの商品単価変更に影響されない

    セキュリティ

    • ロール分離によるアクセス制御（スタッフ/オーナーの2ロール）
    • スタッフ: 注文入力・注文一覧・製造一覧の閲覧・PDF出力（注文関連のみ）
    • オーナー: 全機能（顧客管理・商品管理・請求管理・入金管理・全帳票出力）
    • ユーザー名 + パスワード認証（bcryptによるパスワードハッシュ化）
    • セッションタイムアウト: 8時間（営業時間に合わせた設定）
    • SQLインジェクション・XSSなどのOWASP Top 10への対策

    スケーラビリティ

    • 顧客数: 200社以内を想定
    • 商品数: 50品目以内を想定
    • 1日の注文件数: 100件以内を想定
    • 単店舗向け（マルチテナント不要）

    スコープ外

    明示的にスコープ外とする項目:

    • 複数店舗対応（マルチテナント）
    • POSシステムとの連携
    • 在庫管理
    • 配送ルート管理
    • スマートフォン専用アプリ（iOS / Android）
    • EC / オンライン注文受付
    • 給与・人件費管理
    • 仕入れ管理

    業務フロー（参考）

  ↓
納品書出力（PDF）
  ↓
請求対象選択（締め日に応じて）
  ↓
請求書発行（PDF）
  ↓
入金登録
  ↓
領収書発行（PDF）

    データモデル（概念）

    Customer（顧客）
  ├─ 基本情報（顧客名・電話番号・住所・担当者名・備考）
  └─ 取引条件（税区分・支払方法・締め種別・締め日）

Product（商品）
  └─ 基本情報（商品名・標準単価・税率・有効/無効）

CustomerProductPrice（顧客別単価）
  └─ Customer × Product の単価設定

Order（注文）
  └─ OrderItem（注文明細）
       └─ 注文時点の単価・税率・税額・税区分を固定保存

Invoice（請求書）
  └─ InvoiceItem（請求明細）
       └─ 採番（INV-YYYYMM-NNNN）

Payment（入金）
  └─ Invoice に紐づく入金記録

Receipt（領収書）
